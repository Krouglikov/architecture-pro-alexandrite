# Выбор и настройка мониторинга в системе

## Анализ системы

Мониторинг полезен в любой части приложения, однако проведенный ранее анализ позволяет сформулировать наиболее важные
точки приложения мониторинга. Ими являются:

- CRM API -- подозревается перегрузка сервиса, что может быть причиной потери сообщений из MES;
- MES API -- API открыт для внешних пользователей, испытывает большую нагрузку ("вал заказов"), вызывает нарекания
  пользователей MES из-за длительной загрузки данных;
- MES DB -- может испытывать перегрузку вслед за MES API;
- Message Queue -- важное техническое звено в процессе обработки заказов, может быть частью проблемы с потерей сообщений
  из MES;
- Shop DB -- обслуживает два сервиса сразу (CRM и Интернет-магазин), отказ этой БД будет очень болезненным для работы
  компании.

## Мотивация

Мониторинг позволит:

- во-первых, составить ясное понимание о степени загруженности вычислительной инфраструктуры компании, что позволит
  расходовать денежные ресурсы лишь на те улучшения инфраструктуры, которые действительно необходимы для поддержания
  растущих (в связи с ростом числа клиентов) потребностей системы;
- во-вторых, оперативно выявлять отказы и аварийные ситуации, что позволит быстро реагировать на них, сводя к минимуму
  число недовольных пользователей как среди клиентов, так и среди сотрудников, повышая таким образом их лояльность.

## Выбор подхода к мониторингу

| Компонент     | Подход к мониторингу  | Обоснование                                                                                                                                                                          |
|---------------|-----------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| CRM API       | RED                   | Это HTTP-сервис, обрабатывающий запросы. RED позволяет отслеживать нагрузку (Rate), ошибки (Errors) и задержки (Duration), что критично для выявления перегрузки и потерь сообщений. |
| MES API       | RED + Золотые сигналы | Открыт для внешних пользователей, высокая нагрузка. RED подходит идеально. Можно дополнить «трафиком» и «насыщенностью» из золотых сигналов для полной картины.                      |
| MES DB        | USE                   | База данных — ресурсоёмкий компонент. USE позволяет выявить узкие места: загрузку CPU/диска (Utilization), очереди (Saturation), ошибки подключений (Errors).                        |
| Shop DB       | USE                   | Критичная БД, обслуживает два сервиса. USE помогает вовремя заметить перегрузку по диску, CPU, памяти и избежать отказа.                                                             |
| Message Queue | Золотые сигналы       | Важно отслеживать задержку обработки сообщений (Latency), количество сообщений в очереди (Saturation), ошибки доставки (Errors), нагрузку (Traffic). Подходит лучше, чем RED/USE.    |
| Shop API      | RED                   | Это HTTP-сервис, обрабатывающий запросы. RED позволяет отслеживать нагрузку (Rate), ошибки (Errors) и задержки (Duration), что критично для выявления перегрузки и потерь сообщений. |

- **RED** — подходит для сервисов, где важна задержка, частота запросов и ошибки, особенно для внешних API.
- **USE** — подходит для ресурсов (диски, CPU, память), включая БД. Позволяет понять, не достигнуты ли физические
  пределы системы.
- **Золотые сигналы** — более универсальный подход, сочетающий показатели обслуживания запросов и загрузки ресурсов.

   мониторинга в непосредственной доступности и в архиве, учесть желательность репликации, оценить стоимость необходимых
   ресурсов);
2. Выбрать и развернуть систему сбора и хранения метрик (на основе Prometheus, VictoriaMetrics или иной); развернуть
   агенты мониторинга;
3. Доработать приложения для интеграции с системой мониторинга (обеспечить формирование и передачу метрик);

5. Настроить оповещения (алертинг); развернуть Alertmanager или иное решение;
6. Внедрить мониторинг как рабочий процесс; задокументировать порядок работы персонала с системной мониторинга и
